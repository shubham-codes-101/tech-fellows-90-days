# Day 6: Semantic HTML & Accessibility Review

## 1. Project Overview

The purpose of this task is to review my Day 2 Student Profile page and Day 5 Student Registration Form to improve semantic HTML and accessibility.

## 2. Accessibility Audit

| Check | Finding | Fix / Action Taken |
|---|---|---|
| Semantic HTML | Header, nav, main, section and footer elements are used. | Maintained proper semantic HTML structure. |
| Heading Hierarchy | One H1 and suitable H2 headings are used. | Maintained a clear heading order. |
| Navigation | Navigation links connect to the correct sections. | Added an accessible label to the navigation element. |
| External Links | MDN learning resource opens in a new tab. | Added rel="noopener noreferrer". |
| Image Alt Text | Profile image has descriptive alt text. | Kept meaningful alternative text. |
| Form Labels | Form fields have visible labels connected to their IDs. | Checked label and input associations. |
| Required Fields | Required fields are marked with an asterisk (*). | Added a note explaining the required-field symbol. |
| Radio Buttons | Study Mode options are grouped using fieldset and legend. | Maintained the accessible radio group. |
| Keyboard Navigation | Tab and Shift + Tab work correctly. | Tested keyboard navigation and visible focus indicators. |
| Tables | No data tables are used on the reviewed pages. | No table changes were needed. |

## 3. Keyboard Accessibility Testing

The following keyboard tests were completed:

- Tab key navigation.
- Shift + Tab backward navigation.
- Enter key for navigation links.
- Keyboard interaction with form controls.
- Visible focus indicators on interactive elements.

**Result:** All tested elements worked correctly using the keyboard.

## 4. Reflection

**Q1. What was the first accessibility issue you found?**

The form did not clearly explain which fields were required.

**Q2. How did testing without a mouse change your understanding?**

It helped me understand the importance of keyboard navigation and visible focus indicators.

**Q3. How did you decide the image alt text?**

I used descriptive text to explain what the profile image represents.

**Q4. Which two accessibility checks should you repeat regularly?**

Keyboard navigation and checking form labels and required-field instructions.

## 5. Conclusion

I reviewed my Day 2 Student Profile page and Day 5 Student Registration Form. I checked semantic HTML, heading structure, image alt text, navigation links, form labels, required fields and keyboard accessibility.

This task helped me understand how to create websites that are easier to navigate and use for everyone.
